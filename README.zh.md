# dsh-job-delivery

[English](README.md) | 中文

## 摘要

本候选尚未发行，提供持久任务身份、执行器注册、独立执行和投递队列、产物检查点、取消与显式核对，复用 DSH 原生作业和存储。原生所有者业务页面、模型工具、跨平台发行检查与公开分发尚未完成。

## 使用和授权

目标为 DSH 0.2.2-rc.1 与 Node ^22.19 或 >=24。bundle 插入默认关闭的运行时，依赖原生作业注册表与存储 domain；存储路由须提供持久后端。IM 提供方可以稍后接入，执行器来自已安装的 Host 插件，由操作者选择。

Host 服务为 `ctx.jobDelivery`，通过 `ctx.effect(() => ctx.jobDelivery.register(producer))` 注册执行器。执行器声明并发容量，每个完成的原产物先调用 `context.checkpoint(outputId, parts)`，再报告完成。提交经认证的 `scope`、`actorId`、来源 `operationId`、提供方 ID 与 JSON 参数，把选定模型、音色及用户偏好冻结在参数中。完整来源持久后才允许执行；准入取消在持久化前检查，已经提交的准入仍返回其身份。

这是供可信 Host 使用的服务，消费插件在提交、查询或核对前授权请求者，服务核对所传范围与持久身份。本包没有安装模型工具、公开 HTTP 入口、凭据读取或普通成员权限策略。原生作业仅显示派生任务 ID 与执行状态，完整来源和产物保存在所有者管理的 domain。

## 持久化与恢复

schema 1 原生 domain 使用整库版本校验，坏记录和不支持的版本会令启动失败，不会变成缺失记录。JSON 后端重写一个有界单元，操作者按负载选择容量和适合的原生后端。一个 domain 只有一个写入所有者；多个进程需使用不同 profile 存储或提供排他所有权的后端。所有保留上限均明确拒绝新增工作，保留既有记录。配置覆盖任务数、记录/参数/回执/总保留字节、产物数量、文字/消息段、全局及会话并发、待处理写入和期限。

任务身份包含账号和群/私聊类型；同一来源重放不创建新执行，同身份参数改变则冲突。执行器分别保存产物；不会为了修复投递而自动重做已完成或不确定的计算。启动时，未完成的执行与发送中产物转为不确定。所有者确认未发送后，仅能重排已有产物；再次计算需显式确认未启动过外部执行，已有任何检查点时拒绝重算。

未知发送保持未知，等待核对。“已受理”只表示服务器受理，不证明手机客户端展示。取消先持久保存，再终止在途调用；晚到成功回执仍保留。卸载执行器和运行时会取消并等待实际清理，执行器与传输必须响应取消。禁言/离线预检不调用生产渠道；新来源、规范化入站消息、IM 服务接入或显式 `wake` 可重新检查暂时阻塞。原生作业结束会唤醒作业准入阻塞，保留禁言/离线阻塞。本包不安装轮询定时器或固定重试间隔。

原件消息段引用由生产插件保存的资产，该插件负责原始字节的持久保存和恢复。队列不缩放或重新生成原件。检查点在允许投递前预留完整受支持回执的容量；传输回执非法或过大时明确故障，产物保持未知，不截短后冒充成功，也不自动重试。
