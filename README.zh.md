# dsh-job-delivery

[English](README.md) | 中文

## 摘要

本开发预览提供持久任务身份、执行器注册、独立执行和投递队列、产物检查点、取消与显式核对，复用 DSH 原生作业和存储。同时提供原生所有者配置和任务管理页，业务执行器由独立插件提供。

## 使用和授权

目标为 DSH 0.2.2-rc.1，其声明的 Host 运行环境为 Node >=24.9.0；核心库另测 Node 22.19，只代表实测兼容，不扩大 Host 支持范围。bundle 插入默认关闭的运行时与独立挂载的所有者控制组件，依赖原生作业注册表与存储 domain；存储路由须提供持久后端。IM 提供方可以稍后接入，执行器来自已安装的 Host 插件，由操作者选择。

Host 服务为 `ctx.jobDelivery`，通过 `ctx.effect(() => ctx.jobDelivery.register(producer))` 注册执行器。执行器声明并发容量，每个完成的原产物先调用 `context.checkpoint(outputId, parts)`，再报告完成。提交经认证的 `scope`、`actorId`、来源 `operationId`、提供方 ID 与 JSON 参数，把选定模型、音色及用户偏好冻结在参数中。可用 subscribe(scope, listener) 订阅不含正文的变更，wait(scope, id, signal) 等待单个任务与原生工作清理完成，join(scope, id) 在退出时加入该任务的活跃工作。取消等待不会取消计算；消费方负责取消时，应先 cancel 再 join。完整来源持久后才允许执行；准入取消在持久化前检查，已经提交的准入仍返回其身份。

这是供可信 Host 使用的服务，消费插件在提交、查询或核对前授权请求者，服务核对所传范围与持久身份。本包没有安装模型工具、公开 HTTP 入口、凭据读取或普通成员权限策略。原生作业仅显示派生任务 ID 与执行状态，完整来源和产物保存在所有者管理的 domain。

## 原生所有者页面

打开“插件 → dsh-job-delivery”，启用队列、设置全局与单会话并发，按需展开存储上限。页面区分已保存配置与实际运行配置，显示生成器数量、生成/发送计数、阻塞会话及安全故障状态。停用执行时页面仍可用。

选择完整的租户、网络、账号和群/私聊范围，分页检查任务元数据。接口不返回来源参数、生成文字或媒体位置。停止请求先持久化，再取消在途调用；重新检查会话不会清除结果不确定状态。核对操作必须确认外部结果并携带当前任务版本，确认未发送后仅重发已保存产物。“确认服务端已接受”需填写核对到的消息 ID，不代表手机已展示；已有任何产物时，不允许以“未执行”重新生成。

保存配置与显式重启都要求工作空闲、没有已准入写入。维护租约在 Loader 应用期间拒绝新修改，候选上限逐条检查已有记录。非空的活跃存储域不能切换，先停用再切换会保留旧数据。轮询和操作失败时保留编辑草稿，操作结果通过应用级通知显示。全部九项控制接口独立拒绝非所有者，即使其他策略给该角色全局权限也不能访问。

独立控制组件可配置 targetEntryId、statusRefreshMs、pageSize、maxScopeOptions、maxOutputPreviews、maxPreviewMessageIds；预览截断会明确显示数量，需要检查更多记录时提高对应上限。页面没有删除记录功能。

## 持久化与恢复

schema 1 原生 domain 使用整库版本校验，坏记录和不支持的版本会令启动失败，不会变成缺失记录。JSON 后端重写一个有界单元，操作者按负载选择容量和适合的原生后端。一个 domain 只有一个写入所有者；多个进程需使用不同 profile 存储或提供排他所有权的后端。所有保留上限均明确拒绝新增工作，保留既有记录。配置通过 maxObservers（默认 256）限制观察者数量，并覆盖任务数、记录/参数/回执/总保留字节、产物数量、文字/消息段、全局及会话并发、待处理写入和期限。

任务身份包含账号和群/私聊类型；同一来源重放不创建新执行，同身份参数改变则冲突。执行器分别保存产物；不会为了修复投递而自动重做已完成或不确定的计算。启动时，未完成的执行与发送中产物转为不确定。所有者确认未发送后，仅能重排已有产物；再次计算需显式确认未启动过外部执行，已有任何检查点时拒绝重算。

未知发送保持未知，等待核对。“已受理”只表示服务器受理，不证明手机客户端展示。取消先持久保存，再终止在途调用；晚到成功回执仍保留。卸载执行器和运行时会取消并等待实际清理，执行器与传输必须响应取消。禁言/离线预检不调用生产渠道；新来源、规范化入站消息、IM 服务接入或显式 `wake` 可重新检查暂时阻塞。原生作业结束会唤醒作业准入阻塞，保留禁言/离线阻塞。本包不安装轮询定时器或固定重试间隔。

原件消息段引用由生产插件保存的资产，该插件负责原始字节的持久保存和恢复。队列不缩放或重新生成原件。检查点在允许投递前预留完整受支持回执的容量；传输回执非法或过大时明确故障，产物保持未知，不截短后冒充成功，也不自动重试。

类型服务实现与完整设置对象的升级步骤见源码目录 docs/upgrade-guide/v0.1.0-development/task-observation/guide.zh.md。

## 验证与未完成项

`npm test` 构建并测试合成的原生存储队列。`npm run test:native -- --im-kit-archive <library.tgz> --minimum-free-bytes 1610612736` 把候选装入独立 SDK profile，只强制中断该测试自有进程，再用第二个进程验证恢复。安装前检查显式指定的剩余空间预算，并在 PATH 固定声明的 pnpm。验收先核对固定公开输入的校验值，在不更改锁定 URL 的情况下预热 npm 内容缓存，隔离 pnpm profile 复用同一份已核对的库字节。公开下载失败时可走正常授权的 GitHub CLI，校验失败立即停止。测试使用自制合成来源和本地传输，不发送 QQ 消息、不调用真实模型、不执行 B 站写入。可用 `node scripts/integration/test-web.mjs --im-kit-archive <library.tgz> --browser-cache <playwright-cache> --minimum-free-bytes 1610612736` 验证全新原生 Web profile 和自有无头浏览器。已执行结果保存在同级开发证据中，源码测试不代表模型语义质量评测。

发行验收覆盖本包与原生接口；与真实生图/搜索/语音插件的组合仍需各自的业务验收。面向模型的业务工具由消费插件提供，本包只开放可信 Host 与原生所有者操作。本包不提供完整定时配方、模型执行循环或进程沙箱。支持的应用均经 DSH profile 启动。
